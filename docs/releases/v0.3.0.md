## Summary

A confirmed Profile now becomes something the rest of the product can reason about. The Candidate chooses the model that analyses their Profile and supplies their own key for it. The key goes straight from the browser to the API under a single-use ticket, is stored encrypted, and is never shown again. Profile Curation then reads the Profile role by role and project by project and writes Statements about the Candidate, each quoting the Resume line it came from. The analysis page shows progress as work actually saved, explains a failure in plain words, lets the Candidate stop, retry or run it again under clear rules, and lets them mark each Statement as right or reject it, so a rejected Statement is never used to match a job. Underneath, every Curation runs through a queue on the worker, resumes from the first unsaved unit after a failure, is superseded by a new Resume, embeds its Statements on one platform key into pgvector, and is bounded by a per-Account daily embedding ceiling. The whole path runs in CI against a deterministic stand-in model with no provider key.

## Breaking changes

**Production needs three new settings.** ADR-0023 has the Candidate pay for generation with their own key and the platform pay for embeddings with one key, and neither may silently fall back to the development stand-in. The API and the worker therefore refuse to start in production without `MODEL_ADAPTER=anthropic`, `MODEL_KEY_ENCRYPTION_KEY` (32 bytes in base64, and never the development key published in the repository) and `EMBEDDING_API_KEY`. Migration steps 1 and 6.

**Browser access to the API is narrowed to one route.** CORS now answers only `PUT /account/model` for `WEB_ORIGIN`, with `Authorization` and `Content-Type` and no credentials, so the page can send the Model Key straight to the API without it ever entering the web app process. Every other route sends no CORS headers. The web app calls every other route from its server side, so nothing in the product changes; a browser client calling any other route directly stops working and has to move to a server-side caller (#156, PR #158). Migration step 2.

**The candidate journey changes.** LinkedIn is removed from the product; FR-03 stays in `docs/product/requirements.md` as a removed requirement so the identifiers stay stable. A confirmed Profile now leads to the Model Key step and the analysis page, and the Job Description step stays locked until a Curation completes (#104, #123). Nothing to migrate.

## Migration steps

In order.

1. **Extend the API and worker configuration.** `MODEL_ADAPTER` is `anthropic` in production; blank selects the development stand-in, which production refuses. `MODEL_KEY_ENCRYPTION_KEY` is 32 random bytes in base64, for example from `openssl rand -base64 32`; production refuses the development key published in the repository. Keep it stable once set: a Model Key sealed under one encryption key cannot be opened under another. `EMBEDDING_API_KEY` is the platform key for `text-embedding-3-small`. The compose file passes all three from the root environment with blank defaults, so the local stack and CI run with none of them.
2. **Extend the web configuration.** `API_PUBLIC_URL` is the address the browser reaches the API on, used only to send the Model Key. It defaults to `http://localhost:3001`, and the compose file sets it to `http://localhost:${API_PORT}`. The API's `WEB_ORIGIN` must be the web app's origin, since the key route's preflight answers only that origin.
3. **Rebuild the `api`, `worker` and `web` images.**
4. **Apply the database migrations** with `pnpm db:migrate`, which the compose `migrate` service runs before `api` and `web` start. This release adds four, in order: `0007-create-curation-tables` (`curations`, `curation_units`, and `statements` with a `vector(1536)` embedding and an HNSW index; pgvector has been enabled since `0001`), `0008-create-account-model-choices`, `0009-create-model-key-tickets`, and `0010-create-embedding-allowances` (`embedding_usage`, `embedding_ceiling_overrides`, and `curations.pause_reason`).
5. **Nothing to backfill.** No Curation exists before this release, so the update `0010` makes to paused Curations touches nothing on an upgrade.
6. **The platform embedding key may now be set in a public environment**, because the per-Account ceiling (#133) is enforced before any embedding call is made: 192,000 estimated tokens per Account per UTC day, raised for one Account by a row in `embedding_ceiling_overrides`. The SQL, and the argument for the number, are in `docs/security.md`, "AI pipeline".

## Rollback

Return production to the `v0.2.0` tag and revert the migrations added here with `pnpm db:migrate:down`, run four times, newest first:

- `0010` drops `curations.pause_reason`, `embedding_ceiling_overrides` and `embedding_usage`: the day's counters and every raised ceiling are lost.
- `0009` drops `model_key_tickets`, which only ever holds tickets that live 60 seconds.
- `0008` drops `account_model_choices`: every Candidate's Model Choice and sealed Model Key are deleted, and each Candidate enters their key again after the release is rolled forward.
- `0007` drops `statements`, `curation_units` and `curations`: every Statement, with its Evidence, embedding and review, is deleted. Profiles and Uploaded Resumes are untouched.

Restore the database from a backup taken before this release if the Statements matter. `v0.2.0` answers CORS for `WEB_ORIGIN` on every route again. Jobs left on the `profile-curation` queue in Redis are not consumed by a `v0.2.0` worker; drain the queue or leave it. The `MODEL_ADAPTER`, `MODEL_KEY_ENCRYPTION_KEY`, `EMBEDDING_API_KEY` and `API_PUBLIC_URL` settings can stay; `v0.2.0` does not read them.
